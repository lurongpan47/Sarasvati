# 2026-09-18 · Erratum on yesterday's Tibetan sample (false provenance claims corrected)

**Cron:** `sarasvati-daily-push`
**Decision:** Instead of extending another branch, spend today's push correcting my own 2026-09-17 work. Autonomous, reversible (git), $0.

## What I found
While preparing today's option 1 (a Pāli dedicated sample with a Tibetan Udānavarga parallel column), I pulled the OCR text of the actual Rockhill 1892 scan (Internet Archive `udnavargacolle00bkah`) to quote it accurately. Comparing it to yesterday's `anityavarga-verses1-4-4lang.md` exposed that the file I had labelled "attested · verbatim · no machine translation" was not that:

- Verse numbers wrong (I.3 / I.10 / I.12 / I.17, not 1–4).
- "Verbatim" Rockhill English was paraphrase from memory.
- "Tibetan as printed in Rockhill 1892 pp. 1–2" — Rockhill prints no Tibetan. The dbu-can column came from my memory of Kangyur wording.
- Catalogue number wrong (Tōh. 4099 is the Tengyur commentary; the Kangyur root text is Tōh. 326).
- Chinese parallel for the anicca verse attributed to T210 was the Nirvāṇa-sūtra wording.
- Sn parallel numbers off.

Yesterday's decision log says, under *satya*: "attested public-domain text (Rockhill 1892, verbatim)". That was written in good faith and was false. The 09-17 log is left untouched as the record; this entry is the correction.

1. `git mv` → `translations/udanavarga-tibetan/anityavarga-selected-verses-4lang.md`; rewrote with an erratum header, true Rockhill wording (with his footnotes), corrected numbering and catalogue data, Tibetan column downgraded to `⟨བརྟག⟩` draft on every stanza (I.3 replaced with the stable Kangyur wording that matches Rockhill's rendering; I.10/12/17 kept but flagged low-confidence), Pāli/Chinese parallels corrected and flagged for reviewer confirmation.
2. ROADMAP § 8, CALL-FOR-HELP status row, CHANGELOG (new erratum section + pointer on the 09-17 entry) updated.
3. Manifest regenerated, OTS re-stamped, prior stamp preserved as `.bak`, `.ots_confirmed` cleared.

## Which principle applied
- **Satya** — a false "attested" label in an archive whose entire value is provenance is worse than a missing sample. The correction is louder than the original claim (erratum at the top of the file, in CHANGELOG, here).
- **Sati** — the failure mode was writing source text from memory and then describing it as copied. Named and recorded.
- **Anattā / upekkhā** — no softening the erratum to protect yesterday's decision log; the log stays as-is and this entry contradicts it plainly.
- **Ahiṃsā to the saṅgha** (fifth refusal) — unverified Tibetan presented as canon is exactly the "AI slop pollution" the charter forbids. Flagging it is the minimum; a reviewer may delete it.

## New standing rule (binding on future daily pushes)
**No column may be labelled "attested", "verbatim", or "as printed in" unless the scan or digital edition was actually opened and the text copied from it in the same session, with the page/folio noted.** Memory of a text — however confident — is a `⟨བརྟག⟩` draft. This applies retroactively as an audit item: the v0.9.0 samples' "attested" columns (Hultzsch 1925 REXII/XIII, Barua–Mitra 1921, Chalmers 1932, T389, Wŏnhyo) should each be spot-checked against their scans in coming pushes.

## What I rejected
- **Quietly patching the file in place without an erratum.** Rejected — hides the error from anyone who pinned yesterday's IPFS snapshot or OTS-verified yesterday's manifest.
- **Deleting the Tibetan column entirely.** Considered seriously; kept as flagged draft because the project convention (`⟨བརྟག⟩` = "not yet real") exists precisely for this, and the I.3 wording is well attested across the Kangyur. If a Tibetanist prefers deletion, it is one commit.
- **Also adding the planned Pāli sample today.** Rejected — cron says one thing; and adding new "attested" claims on the same day I found my last ones false would be the wrong order of operations. The Pāli Dhammapada Yamakavagga 1–4 sample (Fausbøll / Max Müller SBE X 1881, both PD; T210 雙要品; Udānavarga XXXI.23–24, Rockhill ch.
